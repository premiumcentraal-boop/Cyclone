## 1. What was built

| Deliverable (plan 76 §7, run 2a) | Built | Where |
|---|---|---|
| Blocks gain `children`, so nesting is possible | A text block holds child blocks, up to 8 levels. `MAX_BLOCKS` (1,000) counts every nested block. References, plain text and search include nested blocks. | `command/pages.py` |
| Edits become operations | `insert`, `delete`, `move`, `set_type`, `set` (properties); `text_insert`, `text_delete` and `mark` within a block; `page` (title and icon). Text positions count characters; a mention counts as one. | `command/pageops.py` |
| Applied transactionally per page, with a per-block version | `POST /v1/cc/pages/{id}/ops`. Every block carries `v`. An operation names the version it was made on. One stale block refuses the whole batch (409 `PAGE_CHANGED`). A batch raises each changed block's version once. | `pages.py` (`PageStore.apply`), `api.py` |
| The three-way merge stays as the fallback | On a 409, Glass fetches the page, merges block by block as before, and sends the merge as operations against the newest versions. | `glass/src/workspace/pageView.ts` |
| The whole-page save is retired | The HTTP route refuses `blocks`; it takes title and icon only. Writers inside the gateway (the AI's tools, imports) hand over a whole page, and the gateway turns it into operations (`diff_ops`). `PageStore.apply` is a page's only content write. | `pages.py`, `api.py` |
| A migration converts every existing page with no loss, checked block by block | Migration 4 stamps `v = 1` on every block of every page. It compares each page before and after, block by block; a page it cannot read stops the migration, and nothing changes. The migrator gained named data steps for this. | `command/store/schema.py`, `migrations.py` |

**Glass:**
- `services/pageops.ts` mirrors the gateway's operations.
- The editor works on a flat list where each block carries its depth. Nested blocks show indented, and a new block takes
  the level of the block above it.
- A save sends only the operations between the gateway's page and the editor's.
- An open page uses the live event's version instead of asking again (one fewer request per remote change).

## 4. Decisions taken in this run

| # | Decision | Why |
|---|---|---|
| S2-1 | Blocks keep their home in `page.blocks` (JSON), now a tree with `v` on each block, rather than a row per block. | Every reader of a page stays as it is; operations give the per-block versions and conflicts the plan asks for. A row per block can come with page history (run 2e) if size demands it. |
| S2-2 | Glass computes operations by **diffing** the editor's page against the gateway's, instead of the editor emitting them. | The editor keeps working unchanged; the same diff serves the AI and imports on the gateway. Run 2b's undo stack builds on the same operations (the property test proves reverse diffs restore pages exactly). |
| S2-3 | A block that keeps its id but changes kind (a paragraph turned into a divider) is **replaced**: deleted, then inserted. | Only text blocks turn into each other in place. |
| S2-4 | **One write path:** title, icon and whole-page writes inside the gateway all go through `apply`. | One place checks versions, validates, indexes and records the change, and the SQL ratchet did not move. |
| S2-5 | Migrations can run **named data steps** (Python) in their transaction, checksummed by name. | Stamping versions inside JSON needs code. A step is never edited once shipped, like SQL. |

## 5. Risks and limits

- **Nesting is shown, not yet made.** Glass shows nested blocks indented and keeps them on save. Making them (Tab and
  Shift+Tab) is run 2d. Today nesting comes from the AI or imports.
- **Enter at the end of a block with children** makes the new block a sibling, so the children move under it. Run 2d
  fixes this with real indentation.
- **Concurrent edits to the same block** are refused and merged by block (the existing merge). Merging inside one block
  (two people typing in the same paragraph) is not part of run 2a.
- **Old Glass tabs:** a tab opened before this build sends whole pages, and the gateway refuses them with a clear
  message. Reloading the tab fixes it.
