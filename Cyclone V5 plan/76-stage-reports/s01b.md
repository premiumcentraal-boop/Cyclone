## 2. How it works

1. **Every change reaches the ledger.** Migration 3 adds outbox triggers on `page`, `cc_table`, `cc_property`,
   `cc_row`, `cc_view` and `routine`. Any write, by any module, becomes an event (run 1a's mechanism, decision S1-1).
2. **The hub keeps it fresh.** While any tab listens, the gateway drains the outbox every 100 ms and wakes the tabs.
3. **Each tab reads from its own cursor.** There is no shared queue. A slow tab only falls behind on its own cursor. A
   send that takes over 5 s closes that tab's socket (code 4429), and it resumes from its cursor when it reconnects.
4. **Glass reloads what changed.** One socket per tab (`services/live.ts`). A view subscribes to its topics and reloads
   its data through its own route when told. A burst for one view becomes one reload. A table skips the reload when the
   event is its own edit of a row it already shows at that version. A table with a cell being edited waits until the
   edit closes.

## 4. Decisions taken in this run

| # | Decision | Why |
|---|---|---|
| S1-6 | Workspace events carry **ids, versions and a digest**, never titles or text. | Glass reads content through its own routes anyway. The ledger stays small, and no written word is copied into an append-only table that can never be edited. |
| S1-7 | **Each tab reads the ledger from its own cursor**; the hub only drains and wakes. | Ordering and resume come free (the ledger is ordered), and a slow tab cannot hold a shared queue. |
| S1-8 | A send over 5 s **closes** the slow tab rather than dropping its events. | It reconnects and resumes from its cursor, so nothing is lost and the gateway never buffers for it. |
| S1-9 | The browser entry opens the channel and hands it to the app; **tests run without one**. | Node has a global `WebSocket`; tests must never open real sockets. |
| S1-10 | A table **defers** a reload while a cell, menu or peek is open. | An edit in progress is never redrawn under the owner. |

## 5. Risks and limits

- **Connections** (the MCP connections list) are not in the ledger yet. A view block over connections now loads when
  it opens and does not refresh on its own. It is the only workspace source without a live topic.
- **The digest** is a fingerprint of a row's content. It reveals nothing on its own but changes whenever the row does.
  Workspace content is plaintext in the same file anyway (threat model, threat 5).
- **The hub's 100 ms beat** runs only while a tab is connected. With no tab it stops, and the engine tick drains as
  before.
- Command Center screens outside the workspace (accounts, connections, ports, the fleet) still poll. They move to the
  channel as they become databases (stage 4).
