## 5. Decisions taken in this run

- **S0-7: the browser benchmark runs on demand and at each stage's end; CI checks its logic.**
  - Why: shared CI machines are too noisy for millisecond budgets, so a CI gate on them would fail at random.
  - Plan 76 §5.2 said "setting it up in CI is part of stage 0". This meets that for the logic, not for the browser run.
- **S0-8: the acceptance script runs as an automated stand-in.**
  - Every pass is checked on the server or the screen.
  - A run by the owner, timed, is OWED (§7).
- **S0-9: the frame budgets are measured as one 60 Hz frame (16.7 ms), and scrolling passes at 57 fps.**
  - The benchmark times a keystroke until the next frame starts, so it cannot tell apart anything faster than one frame.
  - 60 fps is the display's ceiling, so a run cannot reliably show more than about 59.9.

## 6. Measurement problems found and fixed during the run (recorded so nobody repeats them)

- **The first "live change" result (about 100 ms) was false.** The test ran after the undo test on the same page, so
  Glass's own pending save hit a conflict and pulled in the server copy. The measurement now uses a fresh tab with no
  local edits, and takes five samples spread across the polling cycle.
- **The keystroke listener was installed twice on one page**, which doubled one page's samples. It is now installed
  once per page.
- **Glass opens on Devices (`#/devices`), not the workspace.** The acceptance script now starts at the workspace home,
  where an owner would.
- **The first undo "pass" was false:** Enter had not made a block, so there was nothing to undo. The task now checks the
  split happened before it tests undo.
