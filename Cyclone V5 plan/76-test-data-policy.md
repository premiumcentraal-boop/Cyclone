# 76 · Test-data policy

Every test, fixture, benchmark and demo for the platform follows these rules. A change that breaks one is not done.

1. **Synthetic only.** No real person's name, handle, email, phone number, address, photo, message or account appears
   in any fixture, seed, benchmark or screenshot. Handles are numbered (`@acct-00001`), services come from a fixed list
   of example packages and domains (`com.example.notes`, `example.com`), and phones are `bench-phone-NNNN`.
2. **No real secrets, ever.** Test secrets come from the synthetic secret corpus
   (`apps/device-gateway/tests/synthetic_secrets.py`). Its values are obviously fake and follow the shape Cyclone
   refuses (a keyword such as `password` or `token` followed by `:` or `=`). They never imitate a real provider's key
   format, so repository secret scanning never mistakes them for a leak.
3. **The corpus is the yardstick.** Any new place that accepts text adds itself to
   `tests/test_platform_secret_corpus.py`, so every corpus entry is proved to be refused there.
4. **Owner data stays with the owner.** An upgrade or replay check on the owner's own database runs on a copy on the
   owner's machine. The copy, its output and any extract are never committed or uploaded.
5. **Generated, never stored.** Seed data is generated by `scripts/platform/seed.py` from a fixed random seed, so runs
   can be repeated. Generated databases live in temporary folders and are deleted afterwards. No `.db` file is committed.
6. **Benchmarks state their machine.** Every benchmark report names the machine, Python and SQLite versions, so numbers
   are only compared like for like.
