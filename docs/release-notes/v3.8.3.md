## Fixes in this candidate

- **Type auth** — MCP `user_authorized=true` is forwarded into Android `params` (`user_authorized` / `userAuthorized`). Android policy remains authoritative; typed plaintext is not echoed in MCP results.
- **Compact editables** — Page Card `candidates.current` always keeps non-password `editable`/`focused` controls (then clickable hosts) within the 12-slot cap, so overlay `Phone task input` is not dropped.
- **Click verify** — If Android execution succeeded and the goal/clicked label is still on the after-state page, already-on-page is success even when `pageKey` is unchanged. MCP does not report `VERIFICATION_FAILED` solely because `pageChanged` is false.
- **Clickable hosts** — Live click prefers a clickable ancestor when the selected node is `role=generic` / not clickable. Observation-scoped element IDs are unchanged.
- **Settings root** — `phone.open_app` for `com.android.settings` uses MAIN/LAUNCHER plus `CLEAR_TASK|NEW_TASK` so it lands on Settings home, not the last Apps sub-activity.
- **Fleet protocol** — `phone_devices` fleet payloads (`surface=fleet`) are not classified as failed capability actions. `phone_list` is an alias of `phone_devices`.
- **Observe chrome** — Compact observe prefers the foreground application window over `com.android.systemui` chrome when the active root is System UI.

Trust-session pairing crypto is unchanged.
